# AINovelist 本机环境可行性分析报告

**日期**：2026-05-27  
**关联计划**：`plan/项目计划书V0.3.md`  
**分析对象**：在当前 Windows 本机环境中开发 NovelCraft / AINovelist 的可行性  

---

## 1. 结论摘要

当前机器具备开发 NovelCraft / AINovelist MVP 的基础条件，适合推进 Electron + Vue3 + TypeScript + Markdown/JSON 本地存储 + 结构化 Prompt Pipeline 路线。

主要结论：

- MVP 阶段可立即启动开发。
- Beta 阶段大部分能力可在本机完成。
- Pro 阶段涉及 ONNX、本地向量检索、Electron 原生依赖和打包，需要独立 Spike 验证。
- 已完成 pnpm 修复、F 盘缓存/模型目录迁移、C++ Build Tools 检测。

## 4. 对计划阶段的可行性判断

### 4.1 MVP 阶段

可行性：高。

| MVP 模块 | 本机可行性 | 说明 |
|---|---|---|
| Electron 框架 | 高 | CPU、内存、Node 均满足 |
| Vue3 + TypeScript | 高 | Node/npm/pnpm 可用 |
| Markdown/JSON 本地存储 | 高 | 无特殊依赖 |
| Zod Schema 校验 | 高 | 纯 JS/TS 依赖 |
| Markdown 编辑器 | 高 | CodeMirror、Milkdown、TipTap 均可评估 |
| AI Provider | 高 | 云端 API 路线不依赖本地 GPU |
| 基础搜索 | 高 | FlexSearch/MiniSearch 可用 |
| Windows 打包 | 中 | Electron-builder 可行，需注意缓存与签名 |

结论：MVP 可以立即启动。

### 4.2 Beta 阶段

可行性：中高。

Beta 阶段主要是前端与 TypeScript 工程问题，本机性能足够。需要注意：

- 可视化库会增加依赖体积。
- Electron 打包体积会上升。
- 16GB 内存在同时运行 Electron、Vite、索引任务和 AI 相关工具时需要控制并发。
- workspace、模型、缓存应默认使用 F 盘目录。

### 4.3 Pro 阶段

可行性：中等。

Pro 阶段主要风险不是硬件，而是工程链路：

- `onnxruntime-node` 原生包安装与打包。
- Electron 打包后 native binary 能否加载。
- Hugging Face 模型下载与缓存。
- Node 22 与原生依赖兼容性。
- 本地向量索引性能与内存占用。

建议将 ONNX 作为独立 Spike，不阻塞 MVP。

## 5. 推荐技术策略

### 5.1 MVP 推荐组合

| 模块 | 推荐 |
|---|---|
| 脚手架 | electron-vite |
| 包管理器 | pnpm 11.3.0 |
| Node | 当前 Node 22 可先用，必要时准备 Node 20 LTS |
| UI | Vue3 + TypeScript + Element Plus |
| 状态管理 | Pinia |
| 数据校验 | Zod |
| 存储 | Markdown + JSON |
| 搜索 | MiniSearch 或 FlexSearch |
| 编辑器 | 优先 Markdown 编辑器或 CodeMirror |
| AI | 单个云端 Provider |
| 打包 | Electron-builder 或 electron-vite 推荐方案 |

### 5.2 不建议 MVP 引入

- SQLite。
- ONNX Runtime。
- Word 高保真导出。
- 多模型复杂抽象。
- 重型可视化编辑器。

## 6. 风险清单

| 风险等级 | 风险 | 建议 |
|---|---|---|
| 中 | Node 22 偏新 | 遇到原生依赖问题时准备 Node 20 LTS |
| 中 | D 盘空间不算宽裕 | 模型、缓存、workspace 默认走 F 盘 |
| 中 | 国内网络下载 npm/HF 资源可能慢 | 准备镜像源或手动模型下载方案 |
| 中 | 16GB 内存运行 Electron + ONNX + 大项目可能紧 | 后台索引限流，模型按需加载 |
| 中 | VS Build Tools 不在普通 shell PATH 中 | 通过工具链自动定位，或加载 VS 开发环境 |
| 低 | Windows Home 版本 | 不影响当前项目开发 |

## 7. 推荐执行顺序

```text
1. 使用 pnpm 初始化 electron-vite 项目。
2. 先实现 Electron 安全边界：main / preload / renderer。
3. 建立 workspace 配置，默认指向 F:/AINovelistData/workspace。
4. 实现 JSON Repository、Zod Schema、原子保存和备份。
5. 实现 Markdown 章节编辑和知识库浏览。
6. 打通单模型 AI Provider。
7. 完成基础记忆后再做 ONNX Spike。
```

---

## 8. 结论

本机已经具备推进 AINovelist MVP 的开发条件。v0.3 计划应以当前机器为基准，明确：

- pnpm 作为首选包管理器。
- F 盘作为模型、缓存、workspace 和知识库默认位置。
- ONNX 和本地向量检索作为 Spike 验证项。
- Node 22 可先开发，Node 20 LTS 作为原生依赖兼容备选。
- Visual Studio Build Tools 已存在，但原生模块构建仍需在实际依赖安装时验证。
